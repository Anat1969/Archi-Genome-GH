# התקנה ופרסום

[חזרה לתוכן העניינים](../README.md)

מסמך זה מיועד למי שמחזיק/ה גם בקוד המקור. מאגר עם מסמכי תיעוד בלבד אינו אפליקציה ניתנת להרצה.

## סביבת פיתוח

- Node.js בגרסת LTS נתמכת, לדוגמה 22, עם npm; לחלופין Bun.
- קוד המקור הכולל `package.json`, תיקיית `src` והגדרות Vite.
- חיבור פעיל לשירותי האחסון, הנתונים וה-AI. הרצת Vite לבדה אינה מקימה שירותים אלה.

```bash
# מתוך תיקיית קוד המקור
npm ci
npm run dev
```

Vite מוגדר לפורט 8080. ב-Lovable סביבת התצוגה מנוהלת ואין צורך להפעיל שרת נוסף.

חלופה עם Bun: `bun install` ולאחר מכן `bun run dev`. מומלץ להשתמש באותו מנהל חבילות לאורך העבודה ולשמור את קובץ הנעילה המתאים.

## הגדרות סביבה

| שם | היכן נצרך | תפקיד |
| --- | --- | --- |
| `VITE_SUPABASE_URL` | לקוח Lovable Cloud | כתובת שירות הנתונים |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | לקוח Lovable Cloud | מפתח לקוח ציבורי; הרשאות הנתונים עדיין נדרשות |
| `LOVABLE_API_KEY` | פונקציות צד שרת בלבד | גישה ל-Lovable AI |

השמות נשמרו כפי שהם בקוד מטעמי תאימות. אין כאן ערכי מפתחות, מזהי פרויקט או כתובות שירות פנימיות. משתנה המתחיל ב-`VITE_` עלול להיכלל בקוד הדפדפן: לעולם אין לשים בו סוד פרטי.

ב-Lovable הגדרות החיבור וקובצי הלקוח נוצרים ומנוהלים על ידי המערכת. אין לערוך ידנית את `.env`, קובצי הלקוח שנוצרו או מזהי הפרויקט. סודות מוסיפים דרך טופס הסודות המאובטח, לא בקוד ולא ב-GitHub.

## שירותים נדרשים

1. טבלת `genome_analyses`, אילוצי הציונים, הרשאות וטריגר עדכון זמן.
2. מכולת אחסון `genome-images` והרשאות קריאה והעלאה המתאימות לשימוש ללא התחברות.
3. פריסת `analyze-genome` ו-`inspire-genome` עם הרשאת AI זמינה.
4. חברות הטבלה בפרסום Realtime כדי שעדכוני החוברת יגיעו לדפדפן.

המיגרציות בתיקיית `supabase/migrations` מתעדות שינויי סכימה. עצם קיומן במאגר או סנכרון Git אינו מחיל אותן על השירות החי. יש ליישם ולאמת שינויים דרך Lovable Cloud; אין להריץ שוב מיגרציות שכבר הוחלו.

## בדיקות ואריזה מקומית

```bash
npm test
npm run lint
npm run build
npm run preview
```

אלו הפקודות המוגדרות בקוד המקור, לא הצהרה שהן הורצו או עברו במסגרת משימת התיעוד. בניית Vite מפיקה `dist`; היא אינה בדיקת טיפוסים מלאה ואינה בודקת את שירותי הענן.

## פרסום וסנכרון

- ב-Lovable מפרסמים דרך כפתור הפרסום; העלאת תיעוד ל-GitHub אינה מפרסמת את האפליקציה.
- באחסון סטטי חיצוני יש להפנות נתיבים כגון `/archive` ו-`/genome/:id` ל-`index.html`, כדי שרענון קישור ישיר יפעל.
- יש להגדיר משתני לקוח בזמן האריזה ולהשאיר מפתחות AI בצד השרת. לא מובטח שמפתח AI מנוהל של Lovable יעבוד מחוץ לסביבתו ללא הסדרה מתאימה.
- סנכרון הקוד מוגדר ב-Lovable דרך Project settings → Git. חיבור חדש יוצר מאגר חדש; אין אפשרות לחבר מאגר קיים באמצעות סנכרון זה.
- הכתיבה הישירה למסמכים במאגר `Anat1969/Archi-Genome-GH` היא פעולה נפרדת מסנכרון Git.
